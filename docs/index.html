Layers

  • Entry: installDOMPP(doc) installs builders and enhancements onto a document; browser entry auto-installs window.DOMPP.
  • Builders: pure factories (createElementBuilder, createComponentBuilder, createBuilders) with no global dependency.
  • Enhancements: patch Document, Element, and DocumentFragment prototypes to delegate to builders.
  • Core Engine: ElementBuilder (virtual descriptor + reconciliation), ComponentBuilder (render/rerender boundary).

Key Invariants

  • DOM nodes are real browser nodes; no virtual DOM wrapper.
  • ElementBuilder holds a struct descriptor and a live node.
  • Component render returns the rendered result directly (element or flat array) with a non-enumerable .rerender.
  • Fragments and array-returning components produce flat child arrays (per-slot reconciliation).

Installation

flowchart TD
    A[installDOMPP doc] --> B[createBuilders doc]

Per-Document Builder Resolution

Enhancements store builders on doc.__domppBuilders. Prototype methods resolve builders from target.ownerDocument (or the document itself), so the same prototypes work across documents.

sequenceDiagram
    participant U as User code
    participant D as Document
    participant P as Prototype method
    participant B as Builders

    U->>D: document.createElement(tag, props, ...children)
    D->>P: createElement override
    P->>D: getBuilders(this)
    D-->>P: builders
    P->>B: elementBuilder(...)
    B-->>U: ElementBuilder

createComponent

document.createComponent(builder) returns a rendered ElementBuilder (or flat array) extended with .rerender(callback?).

flowchart TD

    D -- yes --> E[materializeArray]
    D -- no --> F[return ElementBuilder]
    E --> G[flat child array + .rerender]
    F --> H[.rerender attached]

﻿# Component Rerender Flow

Render and Rerender

sequenceDiagram
    participant U as User
    participant C as ComponentBuilder
    participant R as Render fn
    participant EB as ElementBuilder
    participant DOM as DOM

    U->>C: createComponent(builder)
    C->>R: builder(rerender)
    R-->>C: tree
    C->>EB: create/reconcile
    EB->>DOM: create nodes
    C-->>U: rendered result + .rerender

    U->>C: result.rerender(callback)
    C->>R: apply callback
    C->>R: builder(rerender) -> next tree
    C->>EB: reconcile (patch in place)
    EB->>DOM: patch nodes
    C-->>U: same identity

Element Root Tag Change

When a component's root tag changes between renders, identity is preserved by replacing the node but keeping the same ElementBuilder instance.

flowchart TD
    A[rerender] --> B{same node?}
    B -- yes --> C[sync struct/events]
    B -- no --> D{same tag?}
    D -- yes --> E[_patchFrom]
    D -- no --> F[create nextNode]
    F --> G[replaceChild in DOM]
    G --> H[update node/struct/events]
    H --> I[keep identity]
    C --> I
    E --> I

Array Component Reconciliation

flowchart TD
    A[materializeArray next] --> B[flatten next items]
    B --> C[for each slot]
    C --> D{nextChild null?}
    D -- yes --> E[remove old node]
    D -- no --> F[reconcileSlot prev, next, oldNode]
    F --> G[update slot node]
    C --> H[remove extra old nodes]
    H --> I[reorder nodes in DOM]
    I --> J[update flat array in place]
